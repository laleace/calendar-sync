# Running calendar-sync with Docker

[Italiano](docker.it.md)

The image runs three services from the same code: `web` (the panel, with the migrations at startup), `worker` (runs the syncs) and `scheduler` (queues the due jobs every minute). All the files are in the [`docker/`](../docker) folder.

| File | What it is |
|---|---|
| `compose.yaml` | The services plus MySQL 8.4. The recommended setup. |
| `compose.sqlite.yaml` | The services with SQLite, no database container. Fine for a personal installation with a few jobs. |
| `compose.build.yaml` | Add-on that builds the image from this checkout instead of pulling it from the registry. |
| `.env.example` | Settings, documented. Copy it to `.env` in the same folder. |

## 1. Install

```bash
git clone https://github.com/laleace/calendar-sync.git
cd calendar-sync/docker
cp .env.example .env
```

In `.env`, set at least:
- `DB_PASSWORD`: a long random password (`openssl rand -hex 24`). It is applied when the database is created: choose it before the first start. Not needed with SQLite.
- `APP_URL`: the address you will open the panel at, such as `http://192.168.1.50:8080`. Google's redirect URI is built from it.
- `APP_LOCALE` (`en` or `it`) and `CALSYNC_TIMEZONE`.

Start it, and create the administrator:

```bash
docker compose up -d
docker compose exec web php artisan calsync:create-admin
```

For SQLite, add `-f compose.sqlite.yaml` to every `docker compose` command (including `exec`). The same applies to the commands below.

To build the image from the source instead of pulling it, add `-f compose.yaml -f compose.build.yaml` and `--build` to the `up` command.

Check that everything is healthy after a couple of minutes:

```bash
docker compose ps
docker compose exec web php artisan calsync:doctor
```

`web`, `worker`, `scheduler` and `db` should be `healthy`. The worker and the scheduler are healthy only while the scheduler ticks every minute and no run is stuck in the queue. On plain HTTP the full `calsync:doctor` reports "APP_URL on HTTPS" and the secure cookie as failed: that is expected until you put HTTPS in front.

## 2. The encryption key

`APP_KEY` encrypts the credentials of your accounts. If `APP_KEY` is empty in `.env`, the first start generates one and stores it in the data volume, as `/app/storage/app/app.key`. **Back it up**: without it, stored passwords and Google tokens become unreadable and have to be entered again.

```bash
docker compose cp web:/app/storage/app/app.key ./app.key
```

Keep that file out of the repository and in a password manager. To manage the key yourself, put it in `.env` instead (`APP_KEY=base64:...`, as generated by `php artisan key:generate --show`).

## 3. HTTPS and a reverse proxy

The container only speaks HTTP on port 8080. To use it beyond your own computer, put a reverse proxy with a certificate in front. The panel must be opened at the same address as `APP_URL`.

In `.env`:

```dotenv
APP_URL=https://calsync.example.com
SESSION_SECURE_COOKIE=true
# Publish the port on this machine only, for a proxy running on the same machine
CALSYNC_BIND=127.0.0.1
```

Then `docker compose up -d`. Caddy gets the certificate by itself:

```caddyfile
calsync.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

With nginx:

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 90s;
}
```

`TRUSTED_PROXIES` decides which proxies may tell the app it is served over HTTPS. The default, `172.16.0.0/12`, covers Docker's usual networks, where a proxy on the same machine appears from. If your Docker uses other address ranges, or the proxy is on another machine, set it to the proxy's address. Do not use `*`.

For a valid certificate on a private address, without opening any port to the Internet, see [https-lan-cloudflare.md](https-lan-cloudflare.md).

## 4. Update

With the published image:

```bash
cd calendar-sync/docker
git pull
docker compose pull
docker compose up -d
```

The `web` container applies the database migrations when it starts. **Before an update that comes with new migrations, back up the database** (below). To pin a version, set `CALSYNC_VERSION` in `.env` (for example `1.0.0`; the default is `latest`).

If you build from the source, `git pull` and then `docker compose -f compose.yaml -f compose.build.yaml up -d --build`.

## 5. Backup and restore

You need two things: the database and the `APP_KEY`.

MySQL:

```bash
docker compose exec db sh -c 'exec mysqldump --single-transaction -u calendar_sync -p"$MYSQL_PASSWORD" calendar_sync' > calendar-sync.sql
```

Restore, on a running stack with the same `APP_KEY`:

```bash
docker compose exec -T db sh -c 'exec mysql -u calendar_sync -p"$MYSQL_PASSWORD" calendar_sync' < calendar-sync.sql
```

SQLite lives in the data volume. Stop the stack for a consistent copy:

```bash
docker compose -f compose.sqlite.yaml stop
docker run --rm -v calendar-sync_data:/data -v "$PWD":/backup alpine tar czf /backup/calendar-sync-data.tgz -C /data .
docker compose -f compose.sqlite.yaml start
```

This archive contains the key (`app.key`) and the database, so store it as carefully as a password.

## 6. Everyday use

| What | How |
|---|---|
| Logs | `docker compose logs -f web worker scheduler` |
| Reset the administrator password | `docker compose exec web php artisan calsync:create-admin` |
| Run a job now, in the foreground | `docker compose exec web php artisan calsync:run {job}` |
| Debug a CalDAV account | `docker compose exec web php artisan calsync:test-account {id} --debug` |
| Stop, keeping the data | `docker compose down` |
| Stop and delete the data | `docker compose down -v` |

After changing `.env`, run `docker compose up -d`: the containers that depend on the changed values are recreated.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `set DB_PASSWORD in .env` when starting | `DB_PASSWORD` is empty. |
| MySQL "Access denied" after changing `DB_PASSWORD` | The password is set only when the database is first created. Change it inside MySQL, or `docker compose down -v` to start from scratch (this deletes the data). |
| Runs stay "Queued" | The worker is not running: `docker compose ps` and `docker compose logs worker`. |
| Page without style, or links start with `http://` | `APP_URL` does not match the address you use, or the proxy does not send `X-Forwarded-Proto` or is not in `TRUSTED_PROXIES`. |
| Google says the redirect URI does not match | `APP_URL/oauth/google/callback` must be registered in Google Cloud Console exactly. See [google-oauth.md](google-oauth.md). |
| "Unreadable credentials" on accounts | The `APP_KEY` differs from the one that saved them. Restore the right key, or enter the passwords again. |
| `web` not healthy right after the first start | It runs all the migrations before serving: give it a minute, then check `docker compose logs web`. |
